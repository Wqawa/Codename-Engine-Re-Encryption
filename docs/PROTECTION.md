# 保护模式

mod 作者可以要求：**这个包加载时，开发者模式必须关着。**

---

## 1. 它是什么，不是什么

**是**：一个存在包里的标记。包加载后开发者模式被关掉，设置里那一项锁成灰色；想解除要密码。

**不是**：安全边界。它挡的是"随手按一下开发者键"的玩家，不是任何有工具的人。
改包里的标记、改 exe、直接改设置文件都能绕过。别把它当 DRM 用。

---

## 2. 标记文件

打包时写进 `data/cne_protect.dat`：

```
CNEZ-PROTECT 1
salt <16 字节 hex>
hash <32 字节 hex>
```

`hash = SHA256( SHA256( salt | "|" + 密码 ) | salt )`——**不存明文密码**，包里翻出来的只是摘要。

---

## 3. 制作：加密 mod 包时

编辑器 `F7` → Encryption Tool → Mod Pack 页：

1. 勾选 **Enable protection mode**
2. 在右边的 `Password:` 框里填密码（有 `Clear` 和 `Copy`）
3. 选 zip、加密

标记会在加密**之前**追加进 zip。用的是追加而不是重打包：原有条目的每一个字节都不动，
所以 200 MB 的包也只多出一个几百字节的条目（`ZipInject`，有 9 项字节级测试盯着）。

> 只有 CNEZ 容器（Enhanced 模式）能带标记。选 Standard 密码 zip 时这一项不起作用——
> 那种格式没有地方放标记文件。

---

## 4. 运行时

1. 加密包加载完 → 读 `data/cne_protect.dat`
2. 有标记 → `Options.protectionMode = true`，同时 `Options.devMode = false`
3. 设置 → Misc 里的 **Protection Mode** 项显示为开启；`Developer Mode` 被锁成灰色
4. 普通 mod / 未加密 mod / 没有标记的包 → 保护模式关闭，该选项灰色不可改

`Developer Mode` 的灰化走的是引擎原有的 `locked` 机制（和着色器预设那一项同一套），
不是新加的开关。

---

## 5. 怎么解除

**目前的入口是启动参数**：

```
CodenameEngine.exe --unlock-protection=你设置的密码
```

密码在包加载后校验，对就这一次运行不锁；错就什么也不发生（不会报错弹窗）。

> 为什么不是设置里弹输入框：引擎没有现成的文本输入对话框，`UIWarningSubstate` 只支持按钮。
> 新做一个带输入框的子状态需要动官方 UI 代码，在没有实机验证的条件下风险比收益大。
> 这一条待补，`MiscOptions` 里那一项现在点了会立即弹回去，不会让设置被绕过。

---

## 6. 与完整性校验的关系

两者互不相干：完整性校验看**文件有没有被改**，保护模式看**这个 mod 要不要关开发者模式**。
一个加密包可以带标记但没有清单，反之亦然。

---

## 7. 已知限制

- 标记可被删除或伪造，保护模式随之失效（这是数据层方案的天花板）
- 只对加密包生效；普通 zip 无法携带标记
- 解锁是**会话级**的：下次启动重新锁定
- 没有 UI 输入框（见第 5 节）
